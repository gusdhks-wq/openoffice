# 모바일 한글 문서 편집

## 목표와 현재 구현

목표는 Android에서 HWP·HWPX를 직접 편집·저장하고, 같은 문서에 외부 ChatGPT/Codex의 구조화 편집과 Drive 파일 동기화를 연결하는 것이다. 일반 텍스트나 Google Docs로 변환하는 것으로 한글 문서 지원을 대신하지 않는다.

현재 모바일은 PC와 같은 고정 버전 rhwp-studio를 오프라인 iframe 편집기로 제공한다. 문서 위에서 커서를 놓고 입력하고, 문단·선택 영역의 서식과 표를 편집한다. 한글 문서가 첫 화면이고 텍스트/Google Docs/PC 연결 화면은 별도 접힌 영역이다. 새 HWP 문서, HWP·HWPX 가져오기, 확대·폭 맞춤·전체 화면, 원본 내보내기와 수정본 저장을 제공한다. HWP를 HWPX로 바꾸는 형식 변환 UI는 아직 없다. 암호·배포용·변경 추적 문서는 편집 대상으로 받지 않는다.

원본은 IndexedDB 작업 공간의 `original`에 보관하며 수정하지 않는다. 검증한 수정본은 `edited`에 별도로 저장한다. 앞선 시험본의 문구 교체 명령은 기존 작업을 여는 마이그레이션에서만 재적용한다. 새 작업은 실제 편집기의 파일 상태를 저장한다. 작업 사본 v2(`.ieum-hwp.json`)는 원본과 수정본을 함께 복구하고, 이전 v1 명령 사본도 계속 가져올 수 있다. 가져온 사본은 새 ID로 저장하며 다른 문서를 덮어쓰지 않는다.

## 저장 순서

1. 편집기의 암호 보호 상태가 명확하게 false인지 확인하고 문서 epoch, 변경 번호, SHA-256 상태를 기록한다.
2. HWP는 PC와 같은 `exportHwpVerify`로 직렬화 결과의 재열기·쪽수를 확인한다. HWPX도 같은 형식으로 내보낸다. 출력 크기와 컨테이너 서명을 검사한다.
3. 새 탭의 폭을 실제 편집기에서 측정해 쓴다. 측정·보존에 실패하면 저장하지 않는다.
4. HWP 필드 종류, 바탕쪽·메모·수식 캡션은 PC의 기존 보존 코드를 재사용한다. 필요한 복원이 거절되면 저장하지 않는다.
5. 수정본을 별도 WASM 문서로 다시 열어 현재 본문·표 요약·쪽수를 비교한다. 저장 중 epoch·변경 번호·해시가 달라지면 다시 시도한다.
6. 마지막 로컬 revision으로 IndexedDB에 저장한다. 다른 탭이 바꾼 revision을 강제 덮어쓰지 않는다. 실패하면 편집기를 유지하고 자동 저장을 일시 중지한다.
7. `한글 파일로 수정본 저장`은 `.edited.hwp` 또는 `.edited.hwpx` 사본을 다운로드하거나 Android 공유 화면으로 전달한다. 원본 내보내기와 구별한다. 로컬 저장 실패 중에도 검증된 파일 사본을 내보내 복구할 수 있지만 기기 저장 성공으로 표시하지 않는다.

입력을 잠시 멈추면 자동 저장하며, 조합 입력 중에는 직렬화하지 않는다. 편집기의 dirty 플래그를 자동 저장이 임의로 지우지 않고 문서 변경 이벤트 번호로 다음 저장 필요 여부를 확인한다. 명시적 파일 저장 중에는 iframe 입력을 잠시 막는다. 저장 도중 변경되면 파일 저장 요청을 보관했다가 안정된 상태에서 다시 시도한다. 미저장 작업이 있으면 문서 전환을 막고 브라우저 이탈 시 경고한다. 백그라운드 전환에서도 저장을 요청하지만 OS 강제 종료 시 완료를 보장하지 않는다.

## PC 코드 재사용 경계

`apps/hwp/src/main`의 hwp5-file, section-tails, field-kinds, tab-widths, tracked-changes는 수정하지 않는다. 모바일 빌드의 한정된 가상 모듈에서 이 파일들을 읽고 브라우저 Buffer, SHA-1 콘텐츠 식별, 압축·CRC 구현에 연결한다. SHA-1은 기존 보존 코드의 레코드 식별용이며 인증에 쓰지 않는다. 압축 스트림의 해제 크기는 제한한다. Electron·Node 파일 접근·구독 프로그램은 모바일 런타임에 포함하지 않는다.

studio는 기존 PC 빌드 스크립트의 고정 tag/commit과 로컬 WASM·플러그인으로 빌드한다. 외부 웹 편집기나 글꼴 CDN을 쓰지 않는다. 편집기·WASM·SDK·브라우저 의존성의 라이선스를 설치본에 포함한다. 오프라인 캐시와 선택적 PC HTTPS 게이트웨이는 정해진 studio 정적 파일만 제공한다.

## 검증과 한계

- 모바일 테스트는 기존 PC 보존 회귀 시험 43개를 브라우저 어댑터에 연결해 그대로 실행한다. 기본 한글 파일 편집·서식·재열기, 암호 상태 미확인/보호 문서 거절, 동시 변경과 잘못된 출력 거절도 검사한다.
- `verify-hwp-browser.mjs`는 휴대폰 크기와 터치 설정의 실제 Chromium에서 한글 조합 입력(CDP IME), 문단 추가, 선택 후 굵게, 두 형식의 수정본 저장·재열기, 표 내용과 원본 불변, 재실행 복구를 검사한다. 모든 요청은 빌드 정적 파일로만 응답한다. 실제 모델·Google 계정·사용자 문서는 사용하지 않는다.
- 이것은 안드로이드 실기기 키보드·파일 선택·공유·강제 종료 검증을 대신하지 않는다. 한컴 한글에서 재열기와 모든 셀 서식·그림·개체 위치·페이지 배치 비교도 별도다. 엔진 검사 통과를 완전한 한컴 호환으로 표시하지 않는다.
- 글꼴 차이와 일부 편집 동작은 별도 검증이 필요하다. 예를 들어 조합 입력 전에 설정한 굵게의 첫 입력 적용은 회귀 항목으로 남기고, 현재 브라우저 시험은 선택 영역에 적용한 서식을 검증한다.

## 남은 연동과 협업

한글 문서에는 아직 외부 AI 도구나 Drive 바이너리 동기화를 붙이지 않았다. 텍스트 문서용 TTT와 Google Docs 동기화는 이 작업 공간과 별개다. 다음 연동은 문서 ID·원본 해시·base revision·operation ID·읽은 범위 사전조건으로 같은 편집기를 제어하고, 검증한 바이너리 수정본을 파일 버전 충돌을 확인하며 동기화해야 한다. 문서 전체를 평문으로 다시 쓰지 않는다.

모바일 담당은 `apps/mobile`과 연동 어댑터를 맡는다. 별도 작업자는 HWP/HWPX 실제 문서·한컴 재열기와 보존 검증을 맡고, `fix/streamed-formula-cells`의 XLSX 수정은 별도 작업으로 유지한다. 상대 작업자의 미커밋 파일을 이미 합친 것으로 간주하지 않는다.
