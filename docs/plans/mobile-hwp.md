# 모바일 한글 문서 작업

## 목표와 현재 범위

최종 목표는 Android에서 HWP·HWPX를 열고 표·서식을 유지하며 수정·저장하고, 같은 문서에 ChatGPT의 구조화 편집과 Drive 파일 동기화를 연결하는 것이다. 일반 텍스트나 Google Docs로 변환하는 것으로 이 목표를 대신하지 않는다.

현재 구현은 원본 파일과 부분 수정 명령을 함께 보관하는 **시험용 작업 공간**이다. 기존 rhwp WASM과 `apps/hwp/studio-plugin/agent-plugin.mjs`를 변경 없이 재사용한다. 원본에서 시작하여 명령을 순서대로 적용하고, 쪽을 canvas에 그린다. 본문과 표 안의 유일한 문구를 교체하고 마지막 수정을 취소할 수 있다. 캔버스 위 커서 입력·글꼴/셀 서식·표 구조 편집은 아직 없다.

수정 명령을 적용한 새 엔진 인스턴스를 만든 후, 원본과 명령을 IndexedDB에 원자적으로 저장한 다음에만 화면의 작업 문서를 바꾼다. 명령 실패나 다른 탭의 변경 충돌 때는 기존 화면과 저장본을 남긴다. 다시 열기는 같은 원본에 같은 명령을 재적용한다. HWP·HWPX 원본 크기 제한은 20MiB, 명령은 200개, 교체 문자열은 각 20,000 UTF-16 코드 단위다. 줄바꿈 교체는 거부한다.

`원본 내보내기 · 수정 전`은 가져온 원본 바이트만 내보낸다. `작업 사본 내보내기`는 원본과 명령이 들어 있는 `.ieum-hwp.json` 복구 파일이며, 이 앱의 한글 문서 열기에서 다시 가져온다. 한글 프로그램용 수정본이 아니다. 복구 파일을 열면 새 작업 문서를 만들어 기존 문서를 덮어쓰지 않는다. 가져온 명령은 스키마·크기 검사와 엔진 재적용 검사를 통과해야 한다.

**수정본을 `.hwp`·`.hwpx`로 내보내는 기능은 아직 제공하지 않는다.** PC 저장 경로의 원본 보존, 바탕쪽·메모·수식 캡션 복원, 탭 폭·필드 처리, 변경 추적·암호 보호, 재열기 검증을 모바일에서도 충족해야 한다. 페이지 수·표 개수만 같다고 서식이 보존됐다고 판정하지 않는다. 특히 모바일의 대체 글꼴은 페이지 배치를 바꿀 수 있다.

## 공통 편집 계약

첫 지원 명령은 `{ id, kind: 'replaceText', find, replacement }`다. `id`는 작업별 UUID이고, 중복은 거부한다. `find`가 문서 전체에서 유일하지 않거나 지원하지 않는 개체 안에 있으면 변경하지 않는다. 찾은 표 안의 글자는 기존 플러그인의 표 경로로 고친다. 문서 전체의 평문을 파일 본문으로 다시 쓰는 경로는 없다.

모바일의 실행 순서는 `현재 revision 읽기 → 명령 검증 → 원본에서 명령 전부 재적용 → expectedRevision으로 저장 → 화면 반영`이다. 저장 충돌을 새 revision으로 강제 덮어쓰지 않는다. 마지막 수정 취소도 원본에서 마지막 명령을 뺀 목록을 재적용한 후 새 revision으로 저장한다. 엔진 내부의 직렬화 사본을 undo 저장소로 쓰지 않는다.

원격 AI 도구를 붙일 때는 명령에 문서 ID, 원본 해시, base revision, operation ID와 읽은 범위의 사전조건을 추가한다. 작업 영수증과 재시도 계약을 서버와 함께 구현하고, 이 검증을 거치지 않는 원격 명령 실행은 열지 않는다. 다음 명령은 표·셀 경로와 현재 내용까지 확인하는 셀 수정, 문단 범위 수정, 허용된 서식 변경이다. 이 원격 계약은 **계획이며 아직 구현하지 않았다.**

## 저장·연동 완료 조건

1. PC 보존 처리와 동등한 모바일 저장 전후 검증 및 원본/수정본 분리.
2. HWP와 HWPX 각각 실제 문서의 본문, 표 셀·서식, 그림, 개체 위치, 바탕쪽·메모, 페이지 배치 비교.
3. 한컴 한글 재열기 결과 확인. 시험 엔진에서 재열기 성공은 한컴 호환성 검증과 구별한다.
4. Android 실기기의 한글 IME, 파일 선택·공유, 앱 종료·복구, 메모리와 큰 문서 검증.
5. 구조화 AI 명령을 같은 명령 실행기로 연결. 현재 TTT의 텍스트 문서 도구는 HWP 도구가 아니다.
6. Drive에 바이너리 원본/수정본을 버전 충돌을 확인하며 동기화. 현재 Google Docs 모드는 한글 문서의 동기화 경로가 아니다.

## 협업 경계

- 모바일/연동 담당: `apps/mobile`, 공통 명령 실행 어댑터, 향후 원격 계약과 바이너리 동기화.
- 별도 검증 작업자: HWP/HWPX 왕복 저장·서식 보존 시험과 오류 목록. 상대 작업자의 미커밋 파일은 이 브랜치에 합쳐진 것으로 간주하지 않는다.
- XLSX 수정은 `fix/streamed-formula-cells`의 별도 작업으로 유지한다.
- 엔진과 기존 PC 저장 경로는 이번 변경에서 수정하지 않는다. 새로운 바이트 보정은 별도 검토 대상으로 남긴다.

## 검증

`npm run test -w @genoffice/mobile`은 실제 WASM으로 HWP·HWPX 본문/표 교체, 중복·오래된 명령 거절, 작업 사본 복구, 다중 탭 충돌, 원본 불변성과 네이티브 base64 파일 공유를 검사한다.

`node apps/mobile/scripts/verify-hwp-browser.mjs`는 빌드 결과를 휴대폰 크기 Chromium에서 열고 실제 WASM의 쪽 표시, 표 안 글자 수정, 원본 바이트 내보내기, 작업 사본 내보내기, 새로고침 복구, 되돌리기와 HWPX 부분 수정을 확인한다. 모든 HTTP 요청은 로컬 빌드 파일로만 응답한다. 실제 Google 계정·모델·사용자 문서는 사용하지 않는다. 이것은 Android 실기기 확인을 대신하지 않는다.
