# 스마트폰에서 쓰는 HTTPS 서버 준비

이 구성은 한 서버에 모바일 웹 화면, 문서 저장소, MCP 연결 주소를 함께 올립니다.
OpenAI API 키가 필요하지 않습니다. 서버·도메인 비용은 호스팅 업체에 따로 내며,
이 저장소의 명령만으로 서버를 구매하거나 계정을 만들지는 않습니다.

## 필요한 것

- Docker Engine과 Compose v2가 있는 Linux 서버. 디스크가 재부팅 뒤에도 남아 있어야 합니다.
- 본인이 관리하는 도메인 또는 서브도메인. 아래의 `documents.example.com`을 실제 주소로 바꿉니다.
- 도메인의 A 레코드가 서버 공인 IP를 가리켜야 합니다. AAAA 레코드가 있으면 IPv6도 올바르게 연결합니다.
- 서버 방화벽의 80·443 포트. 내부 문서 서버의 5182 포트는 공개하지 않습니다.

먼저 서버를 정한 뒤 진행합니다. 결제·도메인 구입·DNS 변경은 자동으로 실행되지 않습니다.
일반 정적 사이트 호스팅이나 실행할 때마다 디스크가 초기화되는 서버는 이 저장 방식에 맞지 않습니다.

## 첫 실행

서버에서 저장소의 이 작업 브랜치를 내려받고 저장소 루트에서 실행합니다.
Node 22.12 이상이 필요합니다. 연결키 파일은 서버에서 생성하고 채팅이나 GitHub에 올리지 않습니다.

```sh
node packages/cloud-documents/scripts/setup.mjs --deploy documents.example.com

docker compose --env-file .env.cloud.deploy \
  -f packages/cloud-documents/deploy/compose.yaml up -d --build
```

처음 빌드할 때 의존성을 내려받아 시간이 걸릴 수 있습니다. Caddy가 인증서를 자동 발급합니다.
키 파일은 소유자만 읽고 쓸 수 있게 생성되며, 기존 파일을 덮어쓰지 않습니다.
`docker compose config` 전체 출력에는 키가 포함되므로 공유하지 마세요.
실행 상태만 보려면 다음 명령을 사용합니다.

```sh
docker compose --env-file .env.cloud.deploy \
  -f packages/cloud-documents/deploy/compose.yaml ps
curl --fail https://documents.example.com/health
```

인증서 발급이 안 되면 DNS, 80·443 포트와 해당 도메인의 기존 웹 서버부터 확인합니다.
같은 서버의 기존 서비스가 이미 이 포트를 쓰면 이 구성을 그대로 실행하지 말고 기존 프록시에 통합합니다.

## 휴대폰과 외부 도구 연결

1. 휴대폰 브라우저에서 `https://documents.example.com`을 엽니다.
2. ‘외부 Codex 문서 연결’에서 같은 HTTPS 주소와 키 파일의 **owner** 키를 입력합니다.
3. 문서를 만들고 ‘문서 동기화’를 누른 뒤, 원하는 문서에만 ‘외부 Codex에 공유’를 켭니다.
4. 외부 클라이언트에는 `/mcp` 주소와 **agent** 키를 설정합니다. 키는 해당 실행 환경의 비밀 설정으로 전달합니다.

모바일 앱의 연결키는 메모리에만 남으므로 앱을 다시 시작하면 재입력이 필요합니다.
공유하면 이전 버전도 외부 도구가 읽을 수 있습니다. 공유 해제는 앞으로의 접근을 막습니다.
이미 읽어 간 내용은 회수할 수 없습니다.

Codex CLI/IDE의 MCP 설정 예시와 HTTP 도구 사용법은 [상위 안내](../README.md)에 있습니다.
클라우드 Codex/ChatGPT에 연결하려면 그 서비스가 지원하는 도구·인증 방식과 실행 중 비밀값 제공을
별도로 확인해야 합니다. 서버를 띄우는 것만으로 현재 대화에 도구가 설치되지는 않습니다.

## 저장·재시작·백업

문서는 `ieumoffice-documents_documents`라는 Docker 볼륨에 남고, 인증서는 별도 볼륨에 남습니다.
`docker compose down`은 기본적으로 볼륨을 보존합니다. `down -v`, 볼륨 삭제 또는 서버 폐기는
문서를 잃을 수 있으므로 백업 전에 실행하지 마세요. 서버를 여러 개로 늘려 같은 저장소를 동시에
열면 안 됩니다.

문서 서버를 정상 중지한 상태에서 호스팅 업체의 디스크/볼륨 백업을 만들고, 복원은 격리된 환경에서
먼저 확인합니다. 백업에는 문서 전체와 수정 이력이 있으므로 비공개로 보관합니다.
비정상 종료 뒤 `writer.lock`이 남으면 다른 프로세스가 같은 볼륨을 쓰지 않는지 확인한 다음에만
복구합니다. 자동으로 잠금을 지우거나 빈 저장소로 초기화하지 않습니다.

이 구성에는 자동 백업, 계정 로그인, 다중 사용자, OAuth 플러그인, 자동 AI 실행이 포함되지 않습니다.
한도와 알려진 제약은 [상위 안내](../README.md#persistence-and-limitations)를 확인하세요.
